# Learn Mode: Per-Page Lesson (Final Version)

## What we're building

Before showing a page's MCQs in **Learn mode**, show a short, beautifully written, AI-generated **lesson** that teaches exactly the concepts that page's questions will test. The learner reads it, clicks **"Start the questions,"** then answers the MCQs. This repeats per page. **Test mode** shows no lesson (you can't pre-teach a test). Works for **both** upload sources and newspaper editions.

The lesson is **question-aware** (generated from the same triaged concepts the MCQs test), **anti-spoiler** (teaches the concept, never reveals which answer is correct), and generated **before** the MCQ loop — so it cannot spoil answers that don't exist yet.

---

## Architecture (5 key decisions)

### 1. Generation timing: inside `_run_page_batch`, before the MCQ loop

The lesson is generated as a **first-class step of cooking a page**, not a separate job. Inside `_run_page_batch` (`generation_graph.py:349-672`), after triage context is loaded (~line 509: page text fetched, `page_coverage` with aspects read) and **before** the MCQ generation loop (line 509+), we generate the lesson.

**Why not a separate off-path job (like `coach.mcq_page`)?** Because the lesson must be ready *before* the questions. `coach.mcq_page` fires from `on_batch_completed` — *after* MCQs land. Wrong order. Generating the lesson inside the cook, before the MCQ loop, guarantees the right sequence. The ~3s LLM call is invisible: the learner is still in "indexing" or reading the lesson while the first MCQ finishes cooking.

**Gated by `serve_mode == "learn"`** — test mode skips lesson generation entirely.

**Best-effort**: wrapped in try/except so a lesson failure never blocks MCQ generation (same defensive pattern as the `coach.mcq_page` enqueue at `question_pool_jobs.py:578-587`).

**Anti-spoiler by construction**: the lesson is generated from the triaged *aspects* (concept labels + cognitive angles) and the page text — the MCQ stems don't exist yet at this point. The lesson and MCQs share the same triage seed, so they're aligned, but the lesson literally cannot reveal answers that haven't been written.

### 2. Storage: new `qb.page_lessons` table via `ArtifactStore`

Following the `document_notes` / `document_topics` precedent exactly (per-page variant):

```sql
CREATE TABLE IF NOT EXISTS qb.page_lessons (
    document_id   UUID NOT NULL REFERENCES qb.documents(id) ON DELETE CASCADE,
    page_number   INT NOT NULL,
    lesson        JSONB NOT NULL DEFAULT '{}'::jsonb,   -- {title, body, policy_version, concepts}
    content_hash  TEXT NOT NULL DEFAULT '',              -- page_content_hash for staleness
    status        TEXT NOT NULL DEFAULT 'pending',       -- pending/generating/ready/failed
    error         TEXT,
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (document_id, page_number)
);
```

- **No `account_id`** — generated content is document-scoped, served to all learners (matches `document_notes`, `document_topics`).
- **No SQLAlchemy model** — accessed via raw SQL through `ArtifactStore` (matches all artifact tables).
- **`content_hash`** — the page-content sha256 (same `_page_content_hash` at `generation_graph.py:108`). On cook, if stored hash ≠ current page hash, regenerate. This is the per-page staleness mechanism.
- **Natural key `(document_id, page_number)`** — `ArtifactStore(table="qb.page_lessons", key_cols=["page_number"], payload_col="lesson")`.

### 3. The prompt: world-class teacher voice (this IS the feature)

New prompt `lesson_page_system` in `prompts.py` `DEFAULTS` dict (DB-overridable via `system_prompts` table — the swappable seam for prose, per ADR 0004). Matches the established Zivo teaching voice (`tutor_system`, `topic_explain_system`, `mcq_grader_system`):

- **Voice**: patient, warm teacher. Plain everyday words. Short sentences. Never stiff, academic, or condescending. Never "the text/passage/page says." Ground in source, never invent.
- **Structure**: one opening sentence on what the page covers, then short paragraphs explaining each key concept. `**bold**` for key terms (first use). Blank lines between paragraphs. `- ` for steps/examples. No markdown headers, no code blocks.
- **Anti-spoiler**: "Teach the concept and reasoning. Do NOT state or hint which answer is correct for any specific question."
- **Length**: 150-250 words. Brief but complete — every sentence earns its place.
- **Question-awareness**: the concepts to teach are injected from triage aspects (`label` + `cognitive_angle`).
- **Output**: fenced ` ```zv-lesson ``` ` JSON block (`{"title": "...", "body": "..."}`) — matches the `zv-mcq` output idiom. Parsed with the same fenced-block extraction pattern.

The call uses the 3-message cache-stable prefix shape: `[system, SUBJECT_MATTER_PREFIX+page_text, instructions(aspects)]` — same as `_generate_draft_mcq` (`mcq_quality.py:143-152`), so the page-text prefix is cacheable across lesson + MCQ calls.

### 4. Frontend: lesson screen in the state machine cascade

**Data**: `page_lesson` field added to the `build_learn_queue_state` return (`question_pool.py:1082-1129`) and to `McqState` (`lib/types.ts`). Arrives free inside the existing SSE `queue` events — no new endpoint, no new fetch. Shape: `{ title, body, status }` or `null`.

**Gate** (`page.tsx`, next to line 1337):
```tsx
const showLesson = mode === "learn"
  && queue?.page_lesson?.status === "ready"
  && !lessonDismissed.has(queue?.current_page ?? 0)
  && !showPageComplete && !showDocumentComplete && !showTestResults
  && !queue?.document_complete;
```
- Uses `mode === "learn"` (not `mode !== "test"`) — belt-and-suspenders since other modes are caught earlier in the ternary.
- **No `!isNewspaper` clause** (unlike `showPageComplete` at line 1338) — the lesson shows in newspaper Learn too.

**Render**: new ternary branch between line 1607 (`reviewIndex`) and 1623 (`McqHeroPanel`) — the live-MCQ fallback. The lesson intercepts before MCQs.

**`<LessonScreen>` component** (`app/(shell)/workspace/_components/LessonScreen.tsx`):
- Centered column, `maw={MCQ_CONTENT_MAX}` (800 — the shared reading measure from `McqCard.tsx:19`).
- Serif `Title` for the lesson heading (Newsreader, `fw={500}`, `letterSpacing: -0.01em` — matching `DocumentCompleteScreen` at `StudyScreens.tsx:363-370`).
- Body: lightweight `<LessonProse>` renderer — splits on `\n\n` into `<Text>` paragraphs (matching `McqFeedbackCard` at `McqCard.tsx:100-174`), handles `**bold**` inline and `- ` bullets. ~25 lines, no markdown dep.
- Single lavender pill button: **"Start the questions"** → adds `current_page` to `lessonDismissed` set → MCQs appear.
- When `page_lesson.status === "generating"`: `<WaitState pet title="Writing your lesson…" body="Reading this page and laying out the key ideas clearly…">` (reuses `WaitState` from `WaitState.tsx:17-48`, same as `NotesView.tsx:180-184`).

**Dismissed tracking**: `useState<Set<number>>`. On page advance (`current_page` increments), the new page isn't in the set → its lesson shows. On "Start the questions," current page is added → MCQs show.

**Re-open pill** (your choice — meta bar): In `StudyMetaBar.tsx`, a small "Lesson" pill appears when `mode === "learn"` + a ready lesson exists for the current page + it's currently dismissed. Clicking removes the page from `lessonDismissed` → lesson re-appears over the MCQ. Rendered as a `Button variant="light" color="lavender"` pill, size compact, placed in the existing meta-bar row.

### 5. Newspaper flow

The newspaper learn→test path (`startNewspaperTest` at `page.tsx:1128-1144`, `onContinueToTest` at `1595-1599`) works unchanged. The lesson shows during the newspaper learn phase (same `showLesson` gate, no `!isNewspaper` suppression). Newspaper "page" = the edition page the MCQ was cooked from (`queue.current_page`). On "Continue to Test," mode flips to test → `showLesson` goes false → no lesson during the test.

## Prompt draft (the quality bar)

The make-or-break artifact. Drafted to match the established Zivo voice and your "written by a teacher, simple words, no AI tone" mandate:

```
You are a patient, warm teacher. A learner is about to answer questions
on this page, and they need a short, clear lesson first.

Write a brief lesson that teaches the key ideas on this page, in plain
everyday language. The learner is smart but new to this topic.

CONCEPTS THE QUESTIONS WILL TEST (teach these):
{aspects as "- label (angle)" list}

RULES:
- Short sentences. Simple words. No jargon without defining it inline.
- Warm and human, never stiff, academic, or condescending.
- Never say "the text says", "the passage states", "according to the
  page", or reference page numbers. Teach directly, as if from your own
  understanding.
- Ground everything in the source material below. Do not invent facts.
- Teach the CONCEPT and the REASONING. Do NOT state or hint which answer
  is correct to any specific question — the learner must still think to
  apply what they learn.
- 150-250 words. Every sentence must earn its place.
- Start with one sentence on what this page covers. Then explain each
  key idea in a short paragraph.

FORMAT:
- Use **bold** for a key term the first time it appears.
- Separate paragraphs with a blank line (press Enter twice).
- Use "- " for a short list of steps or examples, one per line.
- No headings, no markdown headers (#), no code blocks.

OUTPUT — emit ONLY one ```zv-lesson``` block, nothing else:
```zv-lesson
{"title": "one short sentence on what this page covers", "body": "the lesson prose, with **bold** terms, blank-line paragraphs, and - bullets"}
```
```

`policy_version = "qb.lesson.v1"` stamped into the persisted JSONB.

## Edge cases handled

| Case | Behavior |
|------|----------|
| Non-content page | `_run_page_batch` short-circuits at line 373 before lesson gen → `page_lesson` is null → no lesson shown |
| Page with 0 triaged aspects | Skip lesson gen (`cov.get("aspects")` empty) → no lesson |
| Lesson LLM failure | try/except → `status="failed"` → `page_lesson.status !== "ready"` → `showLesson` false → straight to MCQs (learner never blocked) |
| Lesson generating (first cook) | `status="generating"` → `<WaitState pet>` shown → flips to ready when SSE delivers it |
| Page re-indexed (text changed) | `content_hash` mismatch → regenerate on next cook |
| Test mode | `serve_mode != "learn"` → no lesson gen, no lesson shown |
| Newspaper learn | Same gate, no `!isNewspaper` suppression → lesson shows |
| Newspaper test | Mode is test → no lesson |
| Learner re-opens lesson | "Lesson" pill in meta bar → removes page from dismissed set |
| Document complete / page complete / test results | These take priority in the cascade → lesson hidden |

## What is explicitly NOT in scope

- No per-document "overview lesson" (per-page is the unit, per your decision).
- No lesson for test mode (correct — can't pre-teach a test).
- No full quality-evaluation engine for lessons (prose quality is enforced by the prompt + voice rules; programmatic prose eval is a different problem).
- No lesson analytics (read time, skip rate) — future iteration.
- No markdown rendering library (lightweight manual formatter, ~25 lines, keeps the no-deps rule).

# Responsive fix pass — newspaper + cross-device bugs

## Context (verified, not assumed)

Three parallel audits + targeted verification confirm the app is **already ~95% responsive** (correct viewport meta with `interactiveWidget`, Calm Paper theme tokens, AppShell Burger + drawer capped at `min(86vw, 332px)`, `SimpleGrid cols={{base, sm}}` everywhere, dedicated `StudyMobileShell` under 992px, safe-area insets, global `overflow-x: clip`). **There is no systemic desktop-first problem to fix.** Instead there are a few concrete, narrow bugs — one of which (the newspaper day-picker) is almost certainly what you saw.

## Fixes (4 files)

### 1. NEWSPAPER DAY-PICKER — the one you flagged
**`frontend/app/(shell)/practice/newspaper/[slug]/page.tsx:86-124`**

Problem: 3 buttons (`Read analysis` / `Test this edition` / `Learn`) sit in a `wrap="nowrap"` Group. On a ~360–375px phone the row clips off the right edge (the `Shell` sets `overflowX: hidden`, so buttons get cut, not scrolled — matches "badly broken").

Fix: adopt the pattern already used by the sibling catalog page (`newspaper/page.tsx:75-103`):
- Change the action `<Group gap="xs" wrap="nowrap">` → `<Group gap="xs" wrap="wrap">`.
- On each of the three buttons add `fullWidth` and `maw={{ base: "100%", xs: 180 }}` so they stack full-width on phones and sit inline on `xs+`.
- Also drop `wrap="nowrap"` on the header row at line 45 → `wrap="wrap"` so the 56px brand mark + title reflow gracefully on very narrow screens.

No layout system changes, no new components — pure prop alignment with an existing, proven sibling.

### 2. PDF SELECTION POPOVER — overflows on phones
**`frontend/app/(shell)/workspace/_components/PdfReader.tsx:426-457`**

Problem: `popW = onWikipedia ? 520 : 420` is fixed; only `left` is clamped. On a 375px phone with ~6 action buttons (`Ask`/`Explain`/`Dictionary`/`Wikipedia`/`Simplify`/`Save`) the Paper overflows ~57–157px off the right edge.

Fix:
- Make `popW` viewport-aware when narrow: `const popW = isNarrow ? Math.min(window.innerWidth - 24, 360) : (onWikipedia ? 520 : 420);` (the `isNarrow` flag already exists in this component).
- Add to the Paper's `style`: `maxWidth: "calc(100vw - 24px)"`, `flexWrap: "wrap"`, `justifyContent: "center"` so buttons wrap to a second row instead of clipping.
- Leave the desktop path (`popW` 420/520, clamp math) untouched.

### 3. DeleteSourceModal — bring in line with sibling modals
**`frontend/app/(shell)/workspace/_components/DeleteSourceModal.tsx`**

Problem: the only modal missing the `fullScreen={Boolean(isMobile)}` / `radius={isMobile ? 0 : "xl"}` pattern that `AddSourceModal`, `SettingsModal`, and `OnboardingGuide` all use. Content renders acceptably via Mantine defaults but won't match the edge-to-edge mobile treatment used elsewhere.

Fix:
- Add `useMediaQuery(MOBILE_MAX_MQ)` (import from `@/lib/responsive`, same as the other modals).
- On the `<Modal>`: add `fullScreen={Boolean(isMobile)}`, `radius={isMobile ? 0 : "xl"}`, `size={isMobile ? undefined : "md"}`.
- Keep `overlayProps`, `centered`, and the busy guards exactly as-is.

### 4. (Out of scope this pass — documented only)
The `Resume`/`Mains`/`Interview` two-column blocks (`minWidth: 200/220`, `wrap="wrap"`) plumb a `compact` prop but never wire it to layout. They **currently work** via CSS wrapping, so they are not a bug — leaving them as-is keeps this pass low-risk and focused on actual overflow. Flagged for a future deterministic-stacking pass if desired.

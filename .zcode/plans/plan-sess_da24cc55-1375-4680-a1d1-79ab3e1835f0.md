## Security audit — confirmed findings + fixes

Three parallel read-only audits ran against `backend/`, `frontend/`, and `infra/`. After drilling into every flagged site, these are the **real, confirmed bugs**. (Several reported items were verified clean: JWT alg pinning, bcrypt hashing, prod CORS, SQL injection via raw-SQL repos, path traversal in filenames, command injection, committed secrets in tracked files, `dangerouslySetInnerHTML` in frontend.)

### Fix 1 — Stored XSS via chunked-upload content-type bypass  *(Critical)*
**Root cause:** `POST /sources/chunked/init` takes `content_type` straight from the request body and passes it through to MinIO with **no normalization and no allowlist** — bypassing the gate the single-shot path already enforces (`_normalize_upload_content_type` + `ALLOWED_TYPES` in `documents.py:58-84`). `GET /sources/{id}/file` then redirects to a presigned URL served **inline** with that stored type, so an attacker can store `text/html` / `image/svg+xml` with `<script>` and execute JS in any visitor's browser.

**Fix:** Move validation into `document_create.py` (single choke point both paths share) — sniff real type from assembled bytes via the existing `_normalize_upload_content_type`, reject with `415` if not in `ALLOWED_TYPES`, reject images with `422` (matching single-shot). Files: `backend/app/services/document_create.py`, `backend/app/api/documents.py` (export the helpers), `backend/app/services/chunked_upload.py` (re-sniff at complete time from fetched bytes, since init-time type is untrusted).

### Fix 2 — IDOR on saved-notes & brainstorm-ideas  *(High)*
**Root cause:** Both tables are keyed only by `document_id`. `require_document` grants read access to every user on `is_demo`/`is_public` docs, so any authenticated user can `DELETE` or `POST` over anyone else's notes/ideas on the shared demo doc and public practice sources. Files: `services/saved_notes.py`, `services/brainstorm.py`, `api/study.py`.

**Fix:** Add nullable `account_id UUID REFERENCES qb.account(id) ON DELETE SET NULL` to both tables (Alembic `038_note_owner_scope`, additive). Write `account_id` on insert (user.id for authenticated, NULL for guest), add `AND account_id IS NOT DISTINCT FROM :uid` to DELETE. List endpoints filter the same way so each user sees only their own. Legacy NULL rows remain visible to all (backfill not needed — additive, no data loss). New migration `backend/alembic/versions/038_note_owner_scope.py`.

### Fix 3 — No rate limit on auth endpoints  *(High)*
**Root cause:** `/auth/login`, `/auth/signup`, `/auth/google/complete` have no `rate_limit_dependency` — unlimited credential-stuffing. The limiter exists and is wired to nearly every other route.

**Fix:** Add `dependencies=[Depends(rate_limit_dependency)]` to those three routes in `backend/app/api/auth.py`. (The existing per-IP limiter is cluster-safe; keeps the fix to three lines.)

### Fix 4 — FastAPI docs exposed in production  *(Medium)*
**Root cause:** `app = FastAPI(title=..., version=...)` in `main.py:54` never disables docs; ingress routes `/` with Prefix, so `/docs`, `/redoc`, `/openapi.json` are public at `api.zivo.fyi`, leaking the full surface (incl. admin paths).

**Fix:** Conditional constructor — when `settings.is_production`, pass `docs_url=None, redoc_url=None, openapi_url=None`. One edit in `backend/app/main.py`.

### Fix 5 — `python-jose` at vulnerable 3.3.x  *(Low, on auth path)*
CVE-2024-33664 / CVE-2024-33663. Bump `backend/requirements.txt:12` from `>=3.3.0` to `>=3.4.0`.

### Fix 6 — Force attachment on presigned URLs  *(defense-in-depth)*
Even after Fix 1, `presigned_get_url` should override `ResponseContentType=application/octet-stream` + `ResponseContentDisposition=attachment` so user-uploaded bytes are always downloaded, never rendered inline regardless of stored type. Verified safe: the frontend fetches source bytes via `/api/documents/{id}/file` (streamed through `apiFetchBytes`), never by navigating the browser to the presigned URL. One edit in `backend/app/services/storage.py`.

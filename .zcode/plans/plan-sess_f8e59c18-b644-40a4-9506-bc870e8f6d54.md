# Offline Mode — implementation plan

A self-contained **Offline Mode** feature: a learner prepares a signed, server-tracked "offline pack" for an artifact while online (the full active question pool + answer keys + pre-baked feedback + source), studies it with zero network, and replays grades through the real engines on reconnect. Server-authoritative throughout; the trust-model change (answer keys on device) is recorded in ADR 0006.

All four contact points with existing code are additive or minimal: `_sanitize_assertion_payload` is **not modified** (pack builder reads raw rows); the SW-unregister line in `layout.tsx` is **replaced** with registration; the workspace page gets **one offline branch** (not scattered conditionals); the engines, generation workers, and online grade SSE path are **untouched**.

---

## 0. Locked decisions

| Decision | Choice |
|---|---|
| Answer keys on device | **Yes** — recorded in ADR 0006; mitigated by signed, expiring (7-day) packs, personal-study only |
| Pack persistence | **Server-tracked** — `qb.offline_packs` table (Alembic 043) |
| Deck ordering offline | **Pre-baked path** — server orders at build via existing pool query; client just advances |
| Feedback | **Pre-baked** into the pack at build time (ETA job backfills missing `option_feedback`) |
| Deck size | **All active assertions** for the artifact (no cap; could be 1000+) |
| Pack build | **Async ETA job** with `pending→building→ready|failed` + progress (mirrors `artifact_store.py`) |
| Sync conflict | **Server-authoritative** — replay through real engines; server truth overwrites local |
| Local grading integrity | Server **recomputes** correctness from the learner's recorded choice on sync (does not trust a client `correct` flag) |
| Tutor/chat offline | **Unavailable offline** — graceful "Tutor unavailable offline" state |

## 1. Backend

### 1.1 Alembic migration `043_offline_packs.py`
New file `backend/alembic/versions/043_offline_packs.py`. Additive, idempotent, `qb.*` schema (ADR 0002). Shape mirrors `039_page_lessons.py`.

```sql
CREATE TABLE IF NOT EXISTS qb.offline_packs (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  document_id     UUID NOT NULL REFERENCES qb.documents(id) ON DELETE CASCADE,
  account_id      UUID,                      -- NULL for guests
  guest_id        TEXT,                       -- NULL for signed-in
  status          TEXT NOT NULL DEFAULT 'pending',  -- pending|building|ready|failed
  progress        NUMERIC(5,2) NOT NULL DEFAULT 0,  -- 0..100
  question_count  INTEGER NOT NULL DEFAULT 0,
  pack_payload    JSONB,                      -- assembled pack; NULL until ready
  signature       TEXT,                       -- HMAC-SHA256(secret, canonical pack json)
  expires_at      TIMESTAMPTZ NOT NULL,
  created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
  error           TEXT
);
CREATE INDEX IF NOT EXISTS offline_packs_doc_owner_idx
  ON qb.offline_packs (document_id, account_id, guest_id);
```
`down_revision = "042_job_lease_heartbeat"`. `downgrade()` = `DROP TABLE IF EXISTS qb.offline_packs`. Run `backend/scripts/test_alembic_migrations.sh` + `alembic upgrade head` to verify.

### 1.2 Service: `backend/app/services/offline_pack.py`
New module, flat dir (matches `artifact_store.py` structure). `from __future__ import annotations`, typed, raw-SQL repos + pure assembly.

- `create_pack(db, *, document_id, account_id, guest_id) -> dict` — inserts a `pending` row with `expires_at = now() + 7 days`, returns `{id, status}`. (Ownership: exactly one of account_id/guest_id set.)
- `build_pack(db, pack_id) -> None` — the worker entry point. Sets `status='building'`; calls `edition_assertion_ids(db, doc)` (reuse from `question_pool.py:605`) to get the full active deck; for each assertion, loads the **raw** `intel.assertion` row (payload **with** `correct_index`/`correct_indices`/`explanation`/`option_feedback`); backfills missing `option_feedback` via the existing `_persist_option_feedback` path (`mcq_graph.py:303-339`) so feedback exists for every question; assembles the pack object; signs it; stores `pack_payload` + `signature` + `question_count`; sets `status='ready'`, `progress=100`. On error: `status='failed'`, `error=str`. Reports progress increments to the row as it iterates.
- `assemble_pack(document_id, assertions, mastery_snapshot, *, serve_mode) -> dict` — **pure** (DB-free) so it's unit-testable. Returns the pack envelope (see §1.5 shape).
- `sign_pack(payload) -> str` / `verify_pack(payload, signature) -> bool` — pure HMAC helpers using `Settings.secret_key`.
- `get_pack(db, pack_id, *, account_id, guest_id) -> dict | None` — ownership-checked read (status + progress + metadata; payload only via the download endpoint).
- `list_packs(db, *, account_id, guest_id) -> list[dict]` — for the client to discover existing packs per source.
- `revoke_pack(db, pack_id, ...) -> None` — sets `status='revoked'` / deletes row.
- Reads use bound-param `text()` SQL (CONVENTIONS 2.2). No modification to `_sanitize_assertion_payload` — the pack builder selects raw `payload` directly from `intel.assertion`, the same columns the public list query touches plus it does **not** call the sanitizer.

### 1.3 ETA worker for pack build
New `backend/app/eta/worker_offline_pack.py` (+ enqueue helper in `app/services/jobs.py`). Follows the reserve/reclaim/mark loop in `app/eta/worker.py:55-127`. The job payload = `{pack_id}`. Worker calls `offline_pack.build_pack(db, pack_id)`. Run via `run_eta_worker_*.py` entrypoints (already wired for IO+CPU workers). Routes enqueue; workers execute (CONVENTIONS 2.5).

### 1.4 Router: `backend/app/api/offline.py`
New file. `router = APIRouter()`. Register in `backend/app/api/router.py`: `api_router.include_router(offline.router, prefix="/offline", tags=["offline"])` + add to the `from app.api import (...)` block. Endpoints use `dependencies=[Depends(require_csrf_or_guest), Depends(rate_limit_dependency)]` + the `db`/`user`/`guest_id` trio (matches `mcq.py:170-183`).

- `POST /api/offline/packs` body `{document_id: uuid}` → `create_pack` + enqueue job → `201 {id, status:"pending"}`.
- `GET /api/offline/packs/{pack_id}` → status/progress/metadata (ownership-checked). This is the poll target.
- `GET /api/offline/packs/{pack_id}/download` → when `ready` & not expired & signature valid, returns the full `pack_payload` JSON. This is the one endpoint that ships answer keys.
- `GET /api/offline/packs?document_id=…` → list learner's packs for a source (for "already downloaded" badge).
- `DELETE /api/offline/packs/{pack_id}` → revoke/delete.

### 1.5 Grade-batch endpoint: add to `backend/app/api/mcq.py`
`POST /api/mcq/grade/batch`. Request wrapper model (house style — bounded list, matches `coding.py:82-89`):
```python
class GradeBatchIn(BaseModel):
    pack_id: uuid.UUID
    grades: list[GradeIn] = Field(min_length=1, max_length=2000)
```
Handler: verify pack ownership + non-expiry + signature; for each `GradeIn`, resolve the assertion's raw payload, compute `correct` server-side via `grade_verdict(payload, choice_index, choice_indices)` (`mcq_graph.py:364-385`, LLM-free), then call the **existing** `_record_graded_answer(db, g, artifact_id=..., correct=correct, user=user, guest_id=guest_id)`. Replay is safe-by-construction: the `measurement_answer_idempotent` partial unique index (`013_measurement_answer_idempotent.py`) makes duplicate `(learner, assertion)` grades a no-op for calibration. Return `{replayed, mastery: <reconciled snapshot from build_learn_queue_state>}`.

## 2. Frontend

### 2.1 New deps — `frontend/package.json`
- `dexie` (IndexedDB wrapper; typed) — for the pack store + outbox.
- `@serwist/next` + `serwist` — service-worker generation for Next App Router (maintained successor to next-pwa; compatible with Next 16 standalone output). Validate version compat early; **fallback** is a hand-rolled `public/sw.js` with a Workbox-style install/fetch handler if serwist conflicts with standalone output.

### 2.2 Offline module — `frontend/lib/offline/` (new; mirrors `lib/api/` grouping)
- `db.ts` — Dexie schema: `packs` (id, documentId, expiresAt, signature), `assertions` (id, packId, payload-with-keys, sequence), `gradesOutbox` (uuid, packId, assertionId, choiceIndex, choiceIndices, mode, createdAt, synced), `learnerState` (packId → mastery projection), `syncMeta`.
- `engine.ts` — **local study engine** behind the swappable seam (ADR 0004): `currentAssertionId(pack)` returns the next unanswered id in pre-baked order; `localGrade(pack, assertionId, choice)` → `{correct, correct_index, correct_indices, explanation, feedback}` (pure index compare + lookup; mirrors `grade_verdict` + pre-baked feedback). No adaptive logic on the client.
- `prepare.ts` — `POST /api/offline/packs` → poll `GET /api/offline/packs/{id}` until `ready` → `GET .../download` → store in Dexie + Cache API (PDF bytes via `apiFetchBytes` reused from Sidebar). Exposes progress callback.
- `outbox.ts` — `enqueueGrade(grade)`; `drainOutbox()` → `POST /api/mcq/grade/batch` → mark synced / drop.
- `sync.ts` — on `online` event + on mount: drain outbox, apply returned mastery, refresh pack if needed. Idempotent.
- `mode.ts` — `OfflineModeContext` (boolean per artifact + network status from `navigator.onLine`), `useOfflineMode()`, `useOnlineStatus()`.

### 2.3 Service worker + manifest
- `next.config.ts` — wrap config with `withSerwist`, precache app shell, runtime cache for `/_next/static` + fonts (stale-while-revalidate); **network-first for navigations** (online users always get fresh; offline falls back to cached shell). API routes are **not** SW-cached (trust model intact; the pack lives in IndexedDB).
- `frontend/public/manifest.webmanifest` + `<link rel="manifest">` + `themeColor`/`appleWebApp` in `app/layout.tsx` metadata (installability).
- `app/layout.tsx:65-69` — **replace** the `unregister-stale-sw` inline script with SW registration (serwist handles this via its own register component; remove the manual unregister).

### 2.4 Workspace page offline integration — minimal seam
In `frontend/app/(shell)/workspace/[artifactId]/page.tsx`:
- Add an offline branch at the **top** of the data-loading effect (lines ~644-742) and `submitMcq` (lines ~985-1102), gated by `useOfflineMode()`. When offline-active:
  - **Queue**: skip `apiGet(learnQueuePath)` + `EventSource`; instead derive `queue.current_assertion_id` from `engine.currentAssertionId(pack)` and set local `queue` state (same `McqState` shape). The stuck-card poll (744-810) short-circuits.
  - **Assertion content**: pre-seed React Query cache for every pack assertion via `queryClient.setQueryData(queryKeys.assertion(id), …)` so the existing `useAssertionQuery` (273) returns instantly with **no fetch**. Set those queries `staleTime: Infinity` + disable refetch while offline so window-focus can't overwrite the cached-with-keys payload.
  - **Grade**: `submitMcq` calls `engine.localGrade(...)` → writes `gradesOutbox` → calls the **same** `setGradeState`/`setAnsweredHistory` setters with verdict/feedback shaped exactly like the online `onEvent` payload → advances pointer. One branch, reusing existing state setters.
- This keeps the change localized to two functions + cache seeding, not scattered `if offline` checks across 2000 lines.

### 2.5 UI affordances (Mantine-only, Calm Paper tokens)
- **"Prepare offline pack"** action icon in the sidebar `SourceRow` action cluster (`Sidebar.tsx:363-396`) — third `.zivo-source-action` next to Download/Delete, `IconCloudDownload`/`IconWifiOff`. On tap: open a small `Modal` (frosted backdrop) with progress bar while building, then "Ready · N questions · expires in 7 days." Reuses the existing row-hover pattern.

- **Offline mode indicator** in the workspace (`StudyMetaBar` area) when studying from a pack: subtle "Offline" pill; "Tutor unavailable offline" state in the tutor panel (graceful, not a broken input).

No global fetch interceptor exists; the offline path is handled at the workspace-page level (above), not by rewriting `client.ts`. `lib/offline/prepare.ts` and `sync.ts` call the existing `apiGet`/`apiPost`/`apiFetchBytes` helpers for the online prepare/sync round-trips. `client.ts` is **not modified**.

## 5. Risk notes (kept honest)

- **Serwist + Next 16 standalone:** validate early in step 4. If it conflicts, fall back to a hand-rolled `public/sw.js`. Either way the app shell must cache for true reload-offline.
- **Pack size at 1000+ questions:** JSONB in Postgres is fine; the download is a few MB. LLM feedback backfill for many questions is the slow part — that's why build is an async ETA job with progress, and why it reuses the lazy `_persist_option_feedback` (only generates what's missing; already-graded questions are free).
- **Logged-in JWT expiry mid-offline (7/30 days):** guests sync fine (no expiry); a logged-in user whose JWT expired must re-auth before sync. The sync layer surfaces a clear "Session expired, sign in to sync" state rather than failing silently.
- **Window-focus refetch overwriting cached-with-keys assertion:** handled by `staleTime: Infinity` + refetch disable while in offline mode.
- **Scope guard:** notes-outbox and source caching are included (complete feature), but tutor/chat remains explicitly offline-unavailable — no LLM offline, by decision.

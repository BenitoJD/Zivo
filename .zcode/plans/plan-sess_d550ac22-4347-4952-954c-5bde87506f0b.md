## Goal
Replace the hardcoded keyword allowlist exam-relevance gate with an LLM relevance engine, removing the ~200-phrase `_THEME_KEYWORDS`/`_OFF_SYLLABUS_MARKERS` ladder entirely. Keep the deterministic ad/junk detection (it's legitimate heuristic filtering, not hardcoded "if-this-topic-then-relevant" logic). Fallback on LLM failure = permissive (cook the page; downstream usefulness/dedupe/quality gates still filter junk).

## Root cause being fixed
`classify_exam_relevance` (newspaper_ad_filter.py:280-319) hardcodes exam relevance as an exact-keyword match against `_THEME_KEYWORDS`. This fails on paraphrased exam content (e.g. a polity page saying "protests / FIRs / Centre" instead of the literal "supreme court / fundamental rights"). It's a hardcoded if-else ladder that violates the "engines, not if-else" principle.

## Design: mirror the existing `vision.judge_page_has_content` template
The codebase already has a proven LLM-judge pattern (vision.py:133-203). The new relevance engine follows it exactly — same plumbing, same safe-degrade shape, same verdict contract.

## Changes

### 1. New engine: `backend/app/services/newspaper_relevance.py`
An LLM-driven relevance judge, mirroring `judge_page_has_content`:
- **Signature:** `judge_newspaper_relevance(db: Session, page_text: str) -> dict` returns `{"relevant": <bool>, "theme": <str>, "rationale": <str>}`
- **Cache:** `content_hash_key("newspaper_relevance", page_text)` → `cache_get(kind="newspaper_relevance", ...)` before any LLM call; `cache_put` after. Retries never re-bill.
- **Model:** `default_chat_model_id(db)` (text, not vision), `log_tag="newspaper_relevance"`.
- **Prompt:** inline constants (matching vision.py's pattern). System prompt instructs: "Judge whether this newspaper page is relevant to Indian competitive exams (UPSC CSE Prelims GS + State PSC Group-1 + central Group-A): polity, economy, geography, environment, history/culture, IR/security, science-policy, social sector, disaster/governance. Pure entertainment, sports, ads, lifestyle, recipes = not relevant. Judge by *meaning*, not keyword matching. Return JSON only." User prompt demands `{"relevant": <bool>, "theme": "<one topic word>", "rationale": "<one short sentence>"}`.
- **Stable-prefix ordering** (per page_triage_graph): system + page text + JSON-format instruction last (provider prompt-cache friendly).
- **Page-text cap:** truncate page text to a generous limit (e.g. first ~6000 chars) so a 25k-char page doesn't blow the token budget for a yes/no judgment.
- **Safe degrade:** on any exception or unparseable response, return `{"relevant": True, "theme": "", "rationale": "Relevance judge unavailable; allowing."}` (permissive fallback per user choice). Cache this too so retries don't keep calling the LLM.
- **Sync wrapper:** uses `run_coro_in_worker(acomplete_chat(...))` like `judge_page_has_content`, since call sites are in worker threads.

### 2. Rewrite `newspaper_ad_filter.py`
- **KEEP:** `_AD_MARKERS`, `_MASTHEAD_MARKERS`, `classify_page_text` (ad/junk/low_signal/masthead detection — legitimate deterministic filtering), `is_editorial`, the `newspaper_page_verdict` contract (`cook|ad|masthead|low_signal|off_syllabus`), `should_cook_newspaper_page`.
- **REMOVE entirely:** `_OFF_SYLLABUS_MARKERS`, `_THEME_KEYWORDS`, `_THEME_PATTERNS`, `_MIN_THEME_HITS`, `_MIN_DISTINCT_THEMES`, `_theme_hit_map`, `classify_exam_relevance`.
- **Rewire `newspaper_page_verdict`:** after the editorial pass, call the new LLM engine instead of `classify_exam_relevance`. Since the engine needs a `db` Session and `newspaper_page_verdict` is currently `(page_text) -> (verdict, rationale)`, the signature becomes `newspaper_page_verdict(db, page_text)`. The off-syllabus verdict is now driven by the LLM's `relevant=False` → returns `"off_syllabus"` with the LLM's rationale.

### 3. Update the seam: `content_worthiness.py`
- `evaluate_worthiness` currently takes `(page_text, newspaper=True, ...)`. To pass `db` to the relevance engine, add a `db: Session | None = None` parameter (None = no LLM, permissive skip of the relevance check — keeps non-newspaper callers and tests working).
- The newspaper branch calls `newspaper_page_verdict(db, text)` when `db` is provided; when `db is None`, it skips the relevance judgment (permissive — only ad/length checks apply). Reason literals (`newspaper_off_syllabus`, etc.) preserved.

### 4. Update the 3 call sites to pass `db`
- `seo_cook.py:72`: `evaluate_worthiness(page_text=..., newspaper=True, db=db)`
- `page_triage_graph.py:174-208`: pass the triage `db`
- `generation_graph.py:407-446`: pass the cook `db`

### 5. Tests
- **Rewrite** `tests/unit/test_newspaper.py` theme tests (`test_editorial_page_ok`, `test_polity_page_relevant`, `test_lifestyle_without_gs_rejected`, `test_sports_gossip_off_syllabus`): these asserted hardcoded keyword behavior. Replace with: ad-detection tests stay (they test kept heuristics); relevance tests become integration-style (skip if DB/LLM unavailable) that mock or call the LLM engine and assert the *contract* (`cook` for a polity page, `off_syllabus` for sports) not the keywords.
- **Keep** `test_engines_suite.test_worthiness_junk_and_newspaper_seam` — it pins the `newspaper_*` reason literals, which are preserved.
- **Add** an integration test for the new engine's caching + safe-degrade (mirrors the registry-concurrency test pattern: skip if DB unreachable).

### 6. Docs
- Update `docs/CONTENT_WORTHINESS_ENGINE.md`: revise line 58 ("Do not require LLM for the deterministic core") to reflect that ad/junk stays deterministic but exam-relevance is now an LLM judgment (policy `worth_v2` / `qb.worth.v2`).
- Bump the policy version on the LLM-judged verdicts to `worth_v2`.

## Verification plan (after implementation)
1. Unit/integration tests pass (with relevance tests skipping cleanly without a DB).
2. Run the new engine against the same 8 prod newspaper pages I tested earlier — confirm it now cooks the paraphrased polity pages (protests/FIRs/Centre) that the keyword gate rejected, while still rejecting pure entertainment.
3. Confirm cache works (second call for same page text = cache hit, no second LLM bill).
4. Confirm safe-degrade: force an LLM failure → page proceeds permissively (relevant=True), no crash.

## Out of scope
- Not changing the candidate dedup fix from the previous commit (already correct and shipped).
- Not touching the triage graph's LLM classification (separate, already LLM-driven).
- The `newspaper_upsc` content-type tagging stays as-is (orthogonal to relevance).

## Risk note
First-ever cook of a page now costs one extra LLM call (the relevance judge), but it's cached forever after. Net cost is low and the permissive fallback means an LLM outage never blocks cooking.
